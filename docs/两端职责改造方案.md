# 数字乡村平台 · 两端职责改造方案

> 背景：当前平台「农户端」和「管理端」登录后进入同一个页面、同一套导航、同一块大屏，
> 导致「农户端显得多余」「管理端和用户端没啥区别」。
> 本文档是**改造方案**（未动代码），用于先把方向定清楚，再分阶段落地。

---

## 一、问题诊断（现状）

### 根因一句话

**两端都在干同一件事：看「全村的数据大屏」。** 没有区分「我是谁、我来干什么」，所以换了账号看内容差不多，自然撞脸。

### 现状代码事实（已核对）

| 事实 | 现状 | 影响 |
|---|---|---|
| 登录后入口 | 农户 `/login`、管理员 `/admin` **都跳到 `/dashboard`** | 两端共用一个页面 |
| 页面载体 | `DashboardPage.vue` 单文件 7257 行，内含大屏/办事/设置全部逻辑 | 职责混杂，难拆难维护 |
| 默认页 | `currentPage` 默认 `'dashboard'`，即「乡村驾驶舱大屏」 | 农户一登录就看到全村大屏 |
| 左侧导航 | 对所有人**完全一样**：驾驶舱/产业中心/服务中心/治理/生态/村委班子/数据中心/设备中心/设置 | 农户看到一堆管理功能 |
| 角色来源 | 头部一个 `<select>` 下拉「村民/村干部」**随手切换**（临时演示写法） | 角色不是真实身份，是装饰 |

结论：现在的「农户端」不是农户端，是「大屏的游客模式」；「管理端」也不是管理端，是「大屏的完整版」。二者本质是同一块屏的两档显示。

---

## 二、核心原则

- **农户端（村民）= 办「我」的事、看「我」的东西** —— 第一人称「我王友德」
- **管理端（村干部/管理员）= 管「全村」的事、审「别人」的申请** —— 第一人称「我们中堰村」

同一份数据，两端**口径**和**动作**不同：
- 口径：农户看「我这条」，管理看「全村所有条」。
- 动作：农户在「申请/报销/预约/查询」，管理在「审批/处理/统计」。

---

## 三、目标职责对照（模块级）

| 模块（现状 key） | 农户端应该是 | 管理端应该是 | 归属 |
|---|---|---|---|
| 乡村驾驶舱 `dashboard` | **不进入** | 全村态势大屏 | 管理端专属 |
| 数字产业中心 `industry` | 只读「我的产业/我的地块长势」 | 全村产业台账 | 冻结，入口待定 |
| 数字服务中心 `service` | **主入口**：办事大厅（补贴/医保/报销/培训） | 服务台账 + 审批 | 冻结，入口待定 |
| 数字治理中心 `governance` | 「我的上报/我的留言」 | 事件处理 + 网格管理 | 管理端为主 |
| 生态治理中心 `ecology` | 「我要上报 / 我的上报」 | 全村环境监测 + 处置 | 两端，入口分化 |
| 村委班子 `leadership` | 「找谁办事」通讯录 | 班子管理 | 两端共享 |
| 数据中心 `data` | 「我的数据」（我的地/养殖/补贴/医保） | 全村台账 + 明细 + 技术数据 | 已定，沿用 |
| 设备中心 `device/iot/monitor` | **不进入** | 设备/IoT/视频监控 | 管理端专属 |
| 设置 `settings` | 个人设置 | 系统管理（完整） | 已定，沿用 |

> 「已定/沿用」= 之前已经定过方向（数据中心农户端重定位、设置按角色分层），本方案不再重复，直接执行。

## 四、改造方案（结构层）

### 4.1 拆入口 / 路由

现状 `/dashboard` 一条路由两头共用。目标：

| 路由 | 端 | 内容 |
|---|---|---|
| `/farm`（新） | 农户工作台 | 待办 + 我的补贴 + 快捷办事 + 我的数据 |
| `/admin/dashboard`（新） | 管理驾驶舱 | 大屏 + 台账 + 审批 + 系统管理 |

- `/login` 登录成功 → 跳 `/farm`
- `/admin` 登录成功 → 跳 `/admin/dashboard`
- 老的 `/dashboard` 保留为「管理大屏」或 301 到新路由，避免旧链接断。

> 落地方式二选一，建议「**拆成两个独立页面**」而不是继续在一个 7257 行文件里 `v-if` 判断——长期好维护。
> 短期若求快，可先在 `DashboardPage.vue` 内按角色设**不同默认页 + 不同导航**（见 4.2），但终究要拆。

### 4.2 导航按角色分化

现状左侧导航对所有人一样。目标：

**农户端导航（约 6 项）：**
```
我的工作台   → 待办/我的消息/快捷办事
我的地       → 我的地块、我的作物（只读我的）
我的养殖     → 我的养殖档案、记录
办事大厅     → 补贴申请/医保报销/培训预约/进度查询
找谁办事     → 村委班子通讯录
我的数据     → 我的补贴/医保/参保/办事记录（已定口径）
```

**管理端导航（按角色再细分）：**
```
驾驶舱大屏   → 全村态势
产业中心 / 服务中心 / 治理中心 / 生态中心（台账与处置）
审批工作台   → 待审批的补贴/报销/申请（新增）
数据中心     → 全村台账 + 技术数据
系统管理     → 账号/权限/备份/日志（已定分层）
```

> ⚠️ 这一条会**改动左侧导航**。按项目模块隔离规则「禁止修改左侧导航」，本条**需要你明确放行**后才能动，见「七、待确认」。

### 4.3 默认首页（最见效的一刀）

- 农户登录后**第一眼**：`我的工作台`（待办 2 件 ｜ 我的补贴到账 ｜ 我的地块长势 ｜ 快捷办事入口），**不再是全村大屏**。
- 管理员登录后**第一眼**：大屏 + 「待审批」角标。

### 4.4 角色来源收敛

去掉头部「村民/村干部」下拉框（`role-switcher`）这个演示开关：
- 身份由登录态下发（`token`/`adminUser`），不再前端随手切。
- 村干部/网格员作为**真实角色**接入登录，而非下拉切换。

## 五、数据口径规范

| 场景 | 农户端口径 | 管理端口径 |
|---|---|---|
| 补贴 | 我的补贴：到账记录 + 申请入口 | 全村补贴台账 + 审批 |
| 医保养老 | 我的参保、我的报销 | 全村参保率、报销统计 |
| 订单/电商 | 我的订单/我的卖出 | 全村订单、销量、营收 |
| 民宿/旅游 | 我要预订（若有） | 全村民宿/游客统计 |
| 办事记录 | 我的申请记录（跨模块汇总，已定） | 全村办件量、待办队列 |

原则：**农户端永远只出现「我」这条记录；「全村」的统计与明细只出现在管理端。**

## 六、实施分期

### Phase 1 — 先拉开两端（治「撞脸」，见效最快）
1. 农户登录跳 `/farm`，首页改「我的工作台」（不做新页面，先在现有结构里按角色换默认页 + 换导航）。
2. 管理员登录默认进大屏 + 待审批角标。
3. 去掉头部角色下拉框。

### Phase 2 — 管理端「有事可做」
4. 新增「审批工作台」：村干部第一眼看到「待审批的补贴/报销/申请」。
5. 补齐管理端台账（全村地块/养殖/订单/民宿的明细 + 筛选）。

### Phase 3 — 拆文件、接真实权限
6. 把 7257 行的 `DashboardPage.vue` 拆成 `farmer/` 与 `admin/` 两个模块目录。
7. 角色由后端 `token` 下发（去掉前端硬编码身份），对接真实账号体系。

## 八、风险与待确认

1. **左侧导航改造**：违反现有隔离规则，需你确认放行（这是本次的核心动作，不做就治不了「撞脸」）。
2. **产业中心/服务中心冻结 vs 入口归属**：冻结的是「内部实现」，但「农户端能不能进、以什么视角进」需要定——建议农户端把服务中心当「办事大厅」、产业中心当「我的产业」只读，管理端保持完整台账。
3. **是否拆文件**：短期不拆（在一个文件里按角色分）改动小、风险低；长期必须拆。建议 Phase 1/2 不拆，Phase 3 再拆。

---

## 结论

**最小有效改造 = 「农户登录进我的工作台 + 管理登录进大屏/审批台 + 导航按角色分化 + 去掉角色下拉框」。** 这一组做完，两端立刻不再撞脸，农户端从「多余」变成「管理端替代不了的东西」。
